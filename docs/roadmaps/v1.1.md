# v1.1：兼容性证据与输入体验

本阶段承接环境诊断功能，完成真实浏览器验证与输入体验改进。所有未勾选条目均是计划；没有承诺发布日期。环境诊断的实现与验证见 [PR #1](https://github.com/hehuang139/gba-emu/pull/1)。一个 roadmap 对应一个实现 PR，本文为下一阶段的计划 PR。

## 范围与优先级

| 优先级 | 任务 | 交付物与验收 |
| --- | --- | --- |
| P0 | 完成兼容性证据 | 记录 Chromium、Firefox、Safari、Android 和 iOS 的浏览器版本、系统、设备、部署响应头与日期；分别标识自动化、模拟视口和真实设备结果，未测试项保持待验证。 |
| P0 | 验证启动失败路径 | 非安全上下文、缺失隔离响应头、WebGL 不可用、存储禁止或已满时显示具体原因；配额检查失败不影响读取已有游戏库；错误不会修改已有存档。 |
| P0 | 记录低性能设备表现 | 在真实低性能设备运行原创 Star Orbit，分别记录正常运行与倒带的持续帧率、音频中断和内存观测方法；CPU 限速模拟只作为回归信号。 |
| P1 | 自定义手柄映射 | 支持非标准手柄的按钮与轴映射、死区设置、取消录入和恢复默认；设置按设备保存，断连或失焦后不残留按下状态。 |
| P1 | 触屏配置 | 提供布局预设、大小和透明度；设置持久化，支持多点触控、取消事件及横竖屏切换，按钮避开安全区域。 |
| P1 | 键盘与辅助技术 | 纯键盘完成导入、启动、暂停、存取档、退出；检查对话框焦点进入、限制与恢复，动态状态可被辅助技术读取。 |

## 实施顺序

- [ ] 先收集浏览器与设备基线，在兼容性记录中关联失败的最小复现步骤。
- [ ] 完成启动失败回归；探测结果必须与实际可用能力一致，不能仅以 API 对象存在就宣称存档可靠。
- [ ] 抽出独立输入配置与校验函数，旧版偏好设置迁移到默认配置，异常或未知配置不影响游戏启动。
- [ ] 实现手柄映射，再实现触屏预设与持久化；保持核心输入接口和已有键盘映射兼容。
- [ ] 补齐完整键盘流程、窄屏布局和真实设备复测，更新 README 与 CHANGELOG。

## 验证与完成条件

基础检查为 `pnpm test`、`pnpm build`；输入和界面变更运行 `pnpm test:engine`、`pnpm test:ui`，保存流程受影响时同时运行 `pnpm test:saves`。回归测试应覆盖设备断连、窗口失焦、映射取消、刷新恢复和触控取消这些可观察行为。

- [ ] 支持结论都能追溯到设备、版本、日期、步骤和结果。不能以 Playwright WebKit 代替 Safari 真机结论，也不能以窄屏视口代替手机性能测试。
- [ ] 至少一台真实低性能设备完成持续游玩和倒带检查；性能问题记录具体场景与复现资料，不设置未经基线验证的统一帧率门槛。
- [ ] 手柄与触屏设置刷新后保留，旧配置正常迁移，取消或恢复默认不会卡键。
- [ ] 320px 窄屏、常见手机尺寸与横屏没有横向溢出，安全区内的控件可达；PR 附桌面和手机效果图。
- [ ] 纯键盘关键流程与辅助技术人工检查完成；所有适用 CI 检查通过，存档兼容性影响写入 PR。

缺少真机时保持相关任务未完成，并记录缺失设备与待验证步骤，不将其转成已支持结论。

## 阶段边界与后续

本阶段不包含批量备份恢复、离线安装、国际化、核心升级或云同步。v1.1 验收后，下一阶段优先实施数据可携带性：带版本与校验和的备份格式、是否包含 ROM 的选择、恢复预览、冲突策略和事务回滚。PWA 在缓存版本与跨源隔离方案得到验证后单独规划，避免更新混用不兼容的核心资源。
