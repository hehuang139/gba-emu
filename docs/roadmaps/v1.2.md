# v1.2：可携带的游戏库与安全恢复

本阶段规划本地批量备份与恢复，承接 [v1.1 输入体验与兼容性工作](v1.1.md)。本文仅定义任务，所有条目尚未实现，没有承诺发布日期。按「一个 roadmap 一个实现 PR」推进；本规划 PR 与 v1.1 实现 PR 分开提交。

v1.1 尚缺少的真实设备、低性能设备与屏幕阅读器证据仍是发布验收条件，不能因开始备份开发就标记完成。其记录继续维护在 [兼容性矩阵](../compatibility-matrix.md)。

## 范围与优先级

| 优先级 | 任务           | 交付物与验收                                                                                                                                                                                                          |
| ------ | -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P0     | 备份格式与边界 | ZIP 包含版本化 `manifest.json`，记录导出时间、核心版本、游戏内容标识、每个文件的字节数与 SHA-256；定义文件名、路径、单项和累计大小上限。不认识的版本拒绝写入并说明原因。                                              |
| P0     | 一致性导出     | 用户选择游戏范围及是否包含 ROM；默认只导出元数据、电池存档与即时存档。当前运行游戏先暂停并捕获最新 SRAM；数据库各表从同一只读事务获取，避免元数据与存档来自不同时间。保存失败时明确提示，不能声称备份已包含最新进度。 |
| P0     | 只读预览       | 在任何持久化写入前完成 ZIP 边界、manifest、文件校验和、引用关系和游戏标识检查；预览游戏数、存档数、总大小、缺失 ROM、冲突及即时存档核心版本。支持取消且数据库完全不变。                                               |
| P0     | 明确的冲突策略 | 以 ROM 内容标识匹配游戏，按游戏和槽位展示冲突；默认保留本地，可显式选择使用备份。元数据、电池存档和即时存档的选择范围必须可见，不静默覆盖。                                                                           |
| P0     | 原子恢复       | 所有解析、解压和哈希在事务前完成；一次 IndexedDB 写事务完成全部选中项目。配额不足、请求失败或事务中断时整体回滚，已有 ROM 和进度保持不变；恢复时暂停游戏并阻止后台自动存档覆盖恢复结果。                              |
| P1     | 存储整理       | 显示可获得的本站用量与浏览器估计配额；配额未知时仍可使用游戏库。整理入口展示将删除的游戏、ROM 和关联存档，并提供备份入口与现有删除确认。                                                                              |
| P1     | 跨环境恢复证据 | 原创 Star Orbit 在全新浏览器上下文恢复，启动后验证电池进度与即时存档；覆盖含 ROM 与不含 ROM 两种备份，记录真实浏览器和设备结果。                                                                                      |

## 需要先固定的恢复语义

- 不含 ROM 的包恢复至已有相同内容标识的游戏；新环境缺少 ROM 时显示待匹配项，要求用户提供相同哈希的 ROM 后再提交恢复。首版不持久化悬空存档，也不修改现有数据库约束。
- 核心版本不同的即时存档显示兼容性提示，默认不导入该项；电池存档独立选择。未经验证不能承诺不同核心版本的即时存档可用。
- 导出包是本地下载，明确列出包含的内容。不会自动上传或包含未选择的 ROM；公开回归只使用原创或具备明确再分发许可的资源。
- 文件名不是可信路径：拒绝重复条目、路径穿越、异常声明大小、解压超限、缺失引用、额外未声明负载及校验失败，采用现有 ZIP 导入的限制思路。
- 预计恢复占用只是估算；真正写入失败由事务回滚保护。不能因 `navigator.storage.estimate()` 成功就假定一定写得下。

## 实施顺序

- [ ] 固定 manifest v1、限制常量、冲突规则和小型原创测试样本；先完成格式校验与损坏样本测试。
- [ ] 实现一致性导出与是否包含 ROM 的选择，验证下载文件内容和校验和。
- [ ] 实现只读解析与恢复预览，覆盖取消、缺失 ROM、同名不同内容和旧/新版本。
- [ ] 实现事务恢复及后台存档协调，验证中途故障、配额不足与重试。
- [ ] 加入存储整理入口，完成纯键盘、320px 窄屏与横屏检查，提供桌面和手机效果图。
- [ ] 记录跨环境恢复证据，复测 v1.1 未完成设备项，更新 README、CHANGELOG 和兼容性矩阵。

## 验证与完成条件

- [ ] `pnpm test`、`pnpm build` 和所有受影响的现有浏览器套件通过；新增备份恢复套件纳入 CI。
- [ ] 含 ROM 的备份在空白环境恢复后可直接启动；不含 ROM 的备份在匹配 ROM 后恢复相同进度。
- [ ] 每种冲突策略均验证最终数据库内容；取消预览、损坏文件、未来版本、校验失败和配额不足前后数据库完全一致。
- [ ] 恢复过程中注入中间写入失败，确认整个事务回滚；成功后刷新仍可读取全部恢复结果，旧的运行实例不会写回覆盖。
- [ ] 导入与导出达到上限时有明确进度/错误反馈；测量内存峰值并根据真实低性能设备结果调整限制，不直接复制未经验证的大文件门槛。
- [ ] 键盘完成选择、导出、预览、冲突处理、取消与提交；焦点恢复和状态播报可用，窄屏不溢出。
- [ ] v1.1 遗留的实体手柄、Safari/iOS、Android、Firefox、持续倒带性能与屏幕阅读器人工检查逐项记录；缺失环境保持待验证，不以合成输入或视口模拟替代。

## 阶段边界

本阶段不升级 mGBA、不迁移现有单游戏存档格式、不引入账号、云同步、加密备份、PWA 或 Service Worker。若备份语义确需数据库版本升级，须先更新本设计及迁移/回滚验收，再开始实现。下一阶段再单独评估跨源隔离、资源版本一致性和离线缓存更新。
