# v1.2：可携带的游戏库与安全恢复

本阶段实现本地批量备份与恢复，承接 [v1.1 输入体验与兼容性工作](v1.1.md)。2026-09-10 已交付下述软件功能，缺少的真实设备与内存峰值证据仍保持未完成，没有承诺发布日期。按「一个 roadmap 一个实现 PR」推进。

v1.1 尚缺少的真实设备、低性能设备与屏幕阅读器证据仍是发布验收条件，不能因开始备份开发就标记完成。其记录继续维护在 [兼容性矩阵](../compatibility-matrix.md)。

## 需要先固定的恢复语义

- 不含 ROM 的包恢复至已有相同内容标识的游戏；新环境缺少 ROM 时显示待匹配项，要求用户提供相同哈希的 ROM 后再提交恢复。首版不持久化悬空存档，也不修改现有数据库约束。
- 核心版本不同的即时存档显示兼容性提示，默认不导入该项；电池存档独立选择。未经验证不能承诺不同核心版本的即时存档可用。
- 导出包是本地下载，明确列出包含的内容。不会自动上传或包含未选择的 ROM；公开回归只使用原创或具备明确再分发许可的资源。
- 文件名不是可信路径：拒绝重复条目、路径穿越、异常声明大小、解压超限、缺失引用、额外未声明负载及校验失败，采用现有 ZIP 导入的限制思路。
- 预计恢复占用只是估算；真正写入失败由事务回滚保护。不能因 `navigator.storage.estimate()` 成功就假定一定写得下。

## 实施顺序

- [x] 固定 manifest v1、限制常量、冲突规则和小型原创测试样本；完成格式校验与损坏样本测试。
- [x] 实现一致性导出与是否包含 ROM 的选择，验证下载文件内容和校验和。
- [x] 实现只读解析与恢复预览，覆盖取消、缺失 ROM、同名不同内容和旧/新版本。
- [x] 实现事务恢复及后台存档协调，验证中途故障、配额不足与重试。
- [x] 加入存储整理入口，完成纯键盘、320px 窄屏与横屏模拟视口检查，提供桌面和手机效果图。
- [x] 记录 Windows Edge 的全新浏览器上下文恢复证据，更新 README、CHANGELOG 和兼容性矩阵。
- [ ] 复测 v1.1 未完成的真实设备与人工验收项。

格式、限制和恢复语义见 [备份格式 v1](../backup-format.md)。默认只导出所选游戏的信息和存档；界面逐项选择游戏信息、电池存档与槽位，缺 ROM 的游戏默认跳过。未知核心的旧即时档保持来源未知，不能视为当前核心生成。

每批关联 ROM、存档和清单合计上限 64 MiB，省略 ROM 也计入分批边界，避免生成当前恢复过程无法处理的包。导出与解析一致校验此限制。

恢复比较预览指纹，并在写事务内再次比较本地内容，防止异步校验期间的修改被覆盖。进入面板先暂停、排空后台写入和显式捕获最新 SRAM；成功恢复后销毁旧核心实例。仅恢复电池时持久化 `skipAutoState`，保留旧槽位但避免下次自动读取旧进度；新的自动存档会同时清除此标记。数据库仍为版本 1，核心和单游戏存档格式未升级。

## 阶段边界

本轮单元测试 108 项通过，其中备份格式 22 项、存储 28 项。`test:backup` 使用真实 mGBA 与原创 Star Orbit 的合法变体，在 Edge 141.0.3537.71 / Windows 上验证下载、空白上下文含 / 不含 ROM 恢复、旧运行实例隔离、电池单独恢复、配额中途失败回滚与重试。手机尺寸是模拟视口，不代表 Android / iOS 真机；64 MiB 是软件限制，实际多份内存副本的峰值尚未完成低内存设备测量。

本地 `pnpm build` 与九套浏览器检查通过：`engine`、`gamepad` 使用 Vite 开发服务，其余 `ui`、`zip`、`saves`、`keyboard`、`touch`、`startup`、`backup` 使用生产构建预览。键盘退出回归改为验证实际按钮焦点；触控暂停回归等待可观察的暂停与释放状态，避免点击返回后抢在 React effect 前断言。试玩与许可证重建无差异。
